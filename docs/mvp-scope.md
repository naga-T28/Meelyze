## 1. 概要 (Overview)

### 1.1 目的

本ドキュメントでは、`requirements.md` に定義された要件について、2026年8月25日時点のMVPで実装する範囲を明確にする。

MVPでは、開発メンバーが所有するiPhone上で、Meelyzeの主要ユーザーフローが一通り動作することを完成条件とする。

### 1.2 MVP対応区分

| MVP対応 | 意味 |
| --- | --- |
| 対応 | 2026年8月25日までに実装する |
| 一部対応 | 要件の一部をMVPとして実装する |
| 非対応 | 2026年8月25日時点では実装しない |

### 1.3 MVPの基本方針

- `Must` 要件は原則としてMVPで対応する
- `Should` / `Could` 要件は、コアユーザーフローに必要なものを除きMVP以降へ延期する
- `Won't` 要件はMVPでは実装しない
- App Store公開およびTestFlight配布はMVP対象外とする
- iOSは開発時点の最新正式版のみを対象とし、過去iOSバージョンへの対応は正式公開時に検討する
- アプリは安全性を保証せず、注文前に店員へ確認するための補助ツールとして実装する

### 1.4 MVP技術構成

| 項目 | 採用技術 |
| --- | --- |
| UI | SwiftUI |
| ローカルデータ管理 | SwiftData |
| OCR | Apple Vision |
| カメラ | AVFoundation |
| AI / LLM | 未知料理の補助推論・翻訳 |
| 判定 | ローカルDB + Rule Engine |

> `requirements.md` に記載された Flutter / SQLite の技術制約については、現在の開発方針に合わせて SwiftUI / SwiftData に変更する。

## 2. 機能要件 (Functional Requirements)

### FR-1: 撮影・文字認識

| ID | 要件 | 優先度 | MVP対応 | 備考 |
| --- | --- | --- | --- | --- |
| FR-1.1 | 端末内OCRによりメニュー画像から文字列を抽出する | Must | 対応 | Apple Visionを使用する |
| FR-1.2 | OCRの認識言語ヒントを日本語に固定し、誤認識を抑制する | Must | 対応 | 日本語認識を優先する |
| FR-1.3 | 抽出文字列から価格・住所・店名等を除外し、料理名候補を抽出する | Must | 対応 | MVPの主要処理として実装する |
| FR-1.4 | 暗さ・ブレ・傾きを検出し、撮影前にガイドを表示する | Should | 一部対応 | MVPではOCR失敗時の再撮影案内と撮影のコツ表示までとする |
| FR-1.5 | ギャラリーから既存画像を選択して判定する | Could | 非対応 | MVP以降に対応する |
| FR-1.6 | 撮影画像を端末外へ送信しない | Must | 対応 | AI推論時も必要最小限のテキストのみ送信する |

### FR-2: 料理特定・アレルゲン判定

| ID | 要件 | 優先度 | MVP対応 | 備考 |
| --- | --- | --- | --- | --- |

| FR-2.2 | DB照合成立時はDB情報から決定論的にアレルゲンを導出する | Must | 対応 | DB一致料理にはAI推論を使用しない |
| FR-2.3 | 隠れ食材（だし・油脂・調味料）を判定対象に含める | Must | 対応 | 料理データに紐づけて判定する |
| FR-2.4 | DB不一致かつオンライン時はAI推論を実行し、「AI推定・未検証」を表示する | Must | 対応 | 未知料理への補助推論として実装する |

| FR-2.7 | 同一料理名に複数解釈がある場合は最も安全側の解釈を採用する | Must | 対応 | アレルゲンを多く含む解釈を優先する |

## 6. MVP主要ユーザーフロー

```text
初回起動
  ↓
免責事項への同意
  ↓
表示言語・アレルゲン・食事制限を登録
  ↓
メニューを撮影
  ↓
Apple Visionによる端末内OCR
  ↓
料理名候補を抽出・正規化
  ↓
SwiftDataのローカルDBと照合
  │
  ├─ DB一致
  │    ↓
  │  DB情報 + Rule Engineによる決定論的判定
  │
  └─ DB不一致
       │
       ├─ オンライン → AI / LLM補助推論 → 「AI推定・未検証」
       └─ オフライン / 低信頼 / API利用不可 → 「判定不可」
  ↓
三値判定・判定根拠を表示
  ↓
店員への確認を推奨
  ↓
確認カードを表示
  ↓
必要に応じてオンライン自由入力翻訳
```
